FT-REG-002
Result: PASS

Scenario:
Harbor registry service becomes unreachable while DNS resolution remains
available.

Baseline:
Harbor DNS resolution and HTTPS connectivity were healthy. The registry
responded successfully and the signed test image passed the
verify-signed-images evaluation.

Failure Injection:
Modified the Harbor Service selector so that it no longer matched the
Harbor nginx Pod.

Failure Verification:
The Harbor Service remained present but had no backend endpoints.

DNS resolution remained healthy:
harbor-public -> 171.244.199.186

TCP connection to harbor-public:30003 failed immediately with
Connection refused.

Runtime Result:
Kyverno attempted image verification and failed to access the registry:

dial tcp 171.244.199.186:30003: connect: connection refused

The verify-signed-images ImageValidatingPolicy generated a
PolicyViolation event containing the registry connection error.

Because the development policy uses Audit and Warn validation actions,
the API request was admitted with a warning rather than denied.

Recovery:
Restored the original Harbor Service selector. The Harbor endpoint
returned and HTTPS connectivity recovered.

The signed-image admission test was repeated successfully without a
registry connection or image verification error.

Result:
PASS
